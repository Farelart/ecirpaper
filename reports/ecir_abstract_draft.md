# Offline LLM Expansion for Product Search: Effectiveness and Deployment Trade-offs

Product search suffers from vocabulary mismatch between short queries and catalog descriptions. We compare offline LLM product expansion with pretrained sparse and dense retrieval, without ESCI-specific training or online LLM generation. On the English Amazon ESCI candidate-ranking benchmark, comprising 8,956 queries, 181,701 judged pairs, and 164,900 products, structured keywords, synonyms, and usage situations improve BM25 NDCG@10 from 0.7009 to 0.7131, exceeding a three-query-per-product doc2query-T5 configuration at 0.7091. A generated-query control using the same Ling model, metadata, and output allowance reaches 0.7150 with US$1.00 in logged generation charges, versus US$1.42 for structured expansion. E5-small and SPLADE achieve 0.7338 and 0.7368. Separately, exact full-corpus top-10 retrieval on a common Modal T4 host yields median latencies of 4.75 ms for structured BM25, 7.82 ms for E5, and 9.31 ms for SPLADE, including neural query encoding, transfers, and result selection. Neural preparation uses the same T4 resource class; E5 records 24.32 minutes of product processing, with reported preparation compute of US$0.37. We distinguish preparation, index construction, query processing, and deployment charges. The results characterize an effectiveness–latency trade-off while showing that structured generation does not outperform a matched generated-query control.

Suggested keywords: product search; document expansion; BM25; sparse retrieval; efficiency.

## Evidence and limitations (not part of the abstract)

- Primary results: modal_common_t4_verified.md/.json. Earlier local CPU results and the preceding abstract are preserved separately.
- All eight configurations have 181,701 judged ranking rows covering every official query and all candidates without omissions/duplicates. Independent SQL reproduces NDCG@10 and full NDCG within 1e-12. Every timing method has 26,868 complete finite measurements across three shuffled query passes.
- Retrieval ran sequentially in one Modal T4 invocation with one CPU thread: BM25 CPU postings; neural encoding/dot search CUDA; GPU-to-CPU score transfer and deterministic CPU top10 selection included. Warm indexes, 20 warmups, no network serving or ANN. The approximately15x previous local CPU gap is not the primary speed comparison; structured/E5 common-host median ratio is approximately1.65x.
- Neural preparation jobs used T4 with the same CPU/memory resource allocation, but are separate jobs and need not share the same physical host. Ling remains an API deployment measurement and is not self-hosted on T4.
- Both Ling strategies use inclusionai/ling-3.0-flash, identical shortened metadata, temperature0.2, reasoning disabled and220 output tokens/product. Prompts differ. Observed concurrency differs, so their generation spans are not a controlled strategy-throughput comparison.
- Structured generation span44.80min, indexing36.71s, summed recorded phases45.41min. Ling-query generation62.76min, indexing36.09s, sum63.36min. Spans include recovery gaps; they exclude initial setup/final export.
- E5 T4 product processing24.32min plus31.57s index assembly/GPU transfer gives24.85min of recorded phases. SPLADE product processing109.36min plus46.92s gives110.14min. Hosted T5 batch processing119.95min plus35.71s lexical indexing gives120.54min. Neural timers exclude checkpoint/loading overhead, so these are not comparable complete pipeline wall times. Cloud T5 remains a preparation measurement; its preserved local generated queries supply T5 effectiveness/indexing.
- Provider-reported preparation compute: E5 US$0.36649437, SPLADE US$1.52231147, T5 US$1.60737280 before credits. The common eight-method benchmark app's US$0.48260798 compute covers index building, evaluation and all timing passes; it is not a per-method serving-cost estimate. All reported experiment apps, including earlier attempts, total US$4.01109904 including egress as of the report snapshot. Provider adjustments remain possible.
- Quality is judged-candidate ranking, not whole-catalog recall or multi-turn conversational search. Hybrid quality uses full-candidate RRF; timed hybrid search fuses1,000 hits per component with fixed k60. Input shortening for generation versus full512token neural inputs limits cross-family attribution.
