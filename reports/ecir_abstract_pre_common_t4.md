# Offline LLM Expansion for Product Search: Effectiveness and Retrieval Trade-offs

Product search suffers from vocabulary mismatch between short queries and catalog descriptions. We compare inexpensive offline LLM expansion of product metadata with pretrained sparse and dense retrieval, without ESCI-specific training or online LLM generation. On the English Amazon ESCI candidate-ranking benchmark, comprising 8,956 queries, 181,701 judged pairs, and 164,900 products, structured keywords, synonyms, and usage situations improve BM25 NDCG@10 from 0.7009 to 0.7131, exceeding a three-query-per-product doc2query-T5 configuration at 0.7091. However, a generated-query control using the same Ling model, metadata, and output allowance achieves 0.7150 and costs US$1.00 versus US$1.42 in logged generation charges. E5-small and SPLADE achieve 0.7338 and 0.7368, respectively. Separately, exact full-corpus top-10 retrieval on one local CPU thread yields median latencies of 0.83 ms for structured BM25, 12.89 ms for E5-small, and 39.27 ms for SPLADE, including neural query encoding. We report index construction, serialized sizes, and measured preparation costs separately from retrieval. The results expose an effectiveness–latency trade-off for economical offline expansion, while the matched-model control cautions against attributing gains to structured generation itself.

Suggested keywords: product search; document expansion; BM25; sparse retrieval; efficiency.

## Verified evidence and scope (not part of the abstract)

- All eight quality configurations cover every official query and all 181,701 judged pairs. Independent SQL checks find no missing/extra pairs, duplicate pairs, or invalid ranks and reproduce NDCG within 1e-12. Each timing configuration contains 26,868 complete measurements: three shuffled passes over all 8,956 queries.
- Structured minus plain NDCG@10: +0.01215064; exploratory paired 95% bootstrap interval [0.01028948, 0.01401513]. Structured minus T5: +0.00391836; interval [0.00206524, 0.00577098]. Structured minus matched Ling queries: −0.00199668; interval [−0.00355306, −0.00023442]. These use 1,000 query resamples with seed 42 and the standard-library RNG, without multiple-comparison correction. Earlier bootstrap reports used a different RNG and remain preserved.
- SPLADE minus E5: +0.00301186; interval [−0.00015748, 0.00607233]. Its higher mean does not establish a reliable advantage under this exploratory check.
- The actual enrichment model is inclusionai/ling-3.0-flash. Both Ling strategies receive identical saved shortened metadata, temperature 0.2, reasoning disabled and a 220-token output allowance per product. Prompts differ. Each query-expansion baseline generates three queries per product. No ESCI fine-tuning; this T5 configuration does not reproduce the original 40-query setup.
- E5/SPLADE receive full metadata up to 512 tokens; generation uses shortened metadata. Cross-family gaps include input differences.
- Timing uses Apple M4/16GiB, one CPU thread, warm resident indexes, 20 warmups and three shuffled repetitions. Neural query encoding and exact search/top10 selection are included; network serving, model loading and ANN are excluded. Measurements depend on implementation/hardware.
- Quality is judged-candidate ranking, not exhaustive catalog recall or multi-turn search. Hybrid quality uses full-candidate RRF; timed hybrids use RRF k60 over 1,000 hits per component. These are separate protocols.
- Structured indexing takes 16.23s including separately measured tokenization; its serialized index is 113.84MiB. Generation is additional. Neural index assembly excludes document encoding. Sizes exclude shared product-ID mapping, metadata, model weights and resident-memory overhead.
- Hosted T5 saved-batch processing totals 119.95min; reported app compute is US$1.60737. SPLADE product encoding totals 109.36min; reported app compute is US$1.52231. These provider-reported metered costs are before credits and subject to later adjustments. Cloud T5 outputs measure preparation only; original local quality rankings remain intact.

With index construction:45.07min and63.01min. Concurrency varied (observed peak64 versus32); these are deployment spans, not a controlled strategy-speed result. Local E5 monetary compute cost remains unknown. See generation_timing_recovered.json. Different deployment stacks and timing boundaries prevent a universal preparation-speed or cheapest-total-cost claim.
